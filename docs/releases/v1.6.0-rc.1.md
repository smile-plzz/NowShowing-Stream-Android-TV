# 1.6.0-rc.1 — browsing and diagnostics candidate

Version code: 16000. This candidate needs owner TV acceptance; it is not a measured performance certification.

- Home and Browse publish warm cached collections and incremental pairs instead of waiting for an entire shelf. The shared network limit remains two requests. Fresh-cache expiry policy is unchanged.
- Browse refresh works with populated/partial collections; cards remain visible. Sorting no longer clears loading state. Series ranges sort by start year, unknown years last, ties by title.
- Loaded curated collections can be filtered by genre and start year without more metadata requests. Search supports OMDb title/type/year and filter-aware pagination/cache keys. Title words are not plot/theme keyword search.
- Settings → App health offers opt-in 60-second window-frame recording, live memory readings, frozen photo pages with stable report identity/time, reopening and deletion of one saved local report. No automatic upload or network/playback probe.
- All four demo streams and launch buttons are removed. Old diagnostic player routes fail gracefully. Working movie/series providers and user-data tables remain.
- About adds owner profile, source, releases, issues, build variant/commit and verified stack attribution.

## Remaining acceptance

Compare three matched scenarios on the owner's Hisilicon TV, including audit-on/off overhead. Photograph every page, check focus/Back and test playback/provider switching. FrameMetrics reports app-window rendering, not input latency, display drops or video FPS. CPU/GPU use and live rankings are not provided. Phone support remains landscape sideload compatibility.

PR artifacts use development signing. Compare the actual candidate certificate with the installed fingerprint before an in-place update; do not uninstall an existing app merely to bypass a mismatch. No permanent signing claim or release publication is made by this candidate.
